## 🧸 La idea en simple
MCP es un **enchufe universal** para tools: un servidor anuncia sus herramientas y cualquier cliente MCP las puede usar sin código a medida. `langchain-mcp-adapters` convierte cada tool remota en una tool normal de LangChain: el agente no distingue entre una tool MCP y una tuya.

## 📚 Conceptos clave
- `MultiServerMCPClient({"nombre": {"transport": "http", "url": "..."}})` → `await client.get_tools()` → lista de `BaseTool`.
- **Transports:** `stdio` (subproceso local, con `command`/`args`), `http` = *streamable HTTP* (remoto, estándar actual), `sse` (legacy, **deprecado**).
- Por defecto el cliente es *stateless*: cada tool call abre y cierra una sesión.
- Filtrar con `ALLOWED` = mínimo privilegio (el lab deja solo `search_docs_by_lang_chain` y descarta `submit_feedback`).
- Servidores con login: `auth_provider` en la config (lab opcional de OAuth con GitHub; requiere OAuth App y acceso Copilot/MCP).
- Async: `get_tools()` y `agent.ainvoke()` se usan con `await` dentro de `asyncio.run(main())`.

## 🎯 Para el examen
- `sse` está deprecado: para servidores remotos nuevos, `"http"`.
- `stdio` usa `command` + `args`, **no** `url`.
- Las tools MCP son `BaseTool` normales: se pasan en `tools=[...]` como cualquier otra.

## 🧠 Mnemotecnia
