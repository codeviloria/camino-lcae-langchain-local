# M1.4 · System prompt

> **Estado:** ✅ · **Fecha:** 2026-10-06 · **Labs:** `python/m1/m1.4_scratch_agent_butler.py`, `m1.4_scratch_agent_butler_extra_posh.py`, `m1.4_homework_filled.py` · **Modelo:** Nemotron 3 Ultra (OpenRouter `:free`)

## 🧸 La idea en simple
El system prompt es el guion que el actor lee antes de cada escena. Con un solo string cambias la **voz** (mayordomo, pirata), el **dominio** (solo plantas) y las **reglas**, sin tocar el modelo ni las tools. Pero si escribes el guion y no se lo das al actor (`system_prompt=`), no sirve de nada.

## 📚 Conceptos clave
- `create_deep_agent(model=..., system_prompt=SYSTEM_PROMPT, name=...)`.
- **deepagents 0.7:** ya no hay un prompt base largo. Tu `system_prompt` va **primero** en el mensaje de sistema; para algunos modelos (p. ej. `claude-haiku-4-5`) el harness agrega después una sección corta específica del modelo.
- Persona (voz) ≠ scope (dominio + qué hacer fuera de él). El homework practica el scope: **la negativa tiene que sostenerse**.
- En LangSmith, el primer mensaje `system` muestra tu prompt tal cual.

## 🎯 Para el examen
- Definir `SYSTEM_PROMPT` **no basta**: hay que pasarlo con `system_prompt=`. Sin eso, nada de tu persona llega al modelo.
- Trampa (0.7): "si no paso `system_prompt`, el agente usa un prompt base largo". Falso: ya no existe ese prompt base.
- Tener una tool en la lista no obliga al modelo a usarla (`summon_tea` no se llamó).

## 🧠 Mnemotecnia
**"Escribirlo no es pasarlo":** el guion tiene que llegar al actor.
