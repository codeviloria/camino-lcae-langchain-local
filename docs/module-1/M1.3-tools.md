# M1.3 Tools

## Resumen
- Una **tool** es una función de Python que el modelo puede pedir que se ejecute (`@tool` + docstring = descripción para el modelo).
- Se puede probar sola: `tool1.invoke({"x": 467})` → `21.61…`, sin modelo de por medio.
- Se agrega al agente con `create_agent(model, tools=[tool1], system_prompt=...)`.
- Ciclo del agente: **modelo** (decide llamar a la tool) → **tools** (ejecuta Python) → **modelo** (redacta la respuesta con el resultado).

## Tres formas de definir una tool
```python
@tool                                   # nombre = nombre de la función, descripción = docstring
def square_root(x: float) -> float:
    """Calculate the square root of a number"""
    return x ** 0.5

@tool("square_root")                    # nombre explícito, descripción = docstring
def tool1(x: float) -> float:
    """Calculate the square root of a number"""
    return x ** 0.5

@tool("square_root", description="Calculate the square root of a number")   # todo explícito
def tool1(x: float) -> float:
    return x ** 0.5
```
El nombre que ve el modelo es `square_root` en los tres casos, aunque la variable de Python se llame `tool1`.

## Conceptos clave
| Concepto | Qué es | Nota |
|---|---|---|
| `@tool` | Convierte una función en tool | Nombre, docstring y type hints → esquema JSON que ve el modelo |
| Tool calling | El modelo devuelve `tool_calls` en vez de texto | El modelo **debe** soportar tools (`ollama show <modelo>` → Capabilities) |
| Nodo `model` / nodo `tools` | Los dos pasos del loop de `create_agent` | Se ven con `stream_mode="updates"` |
| `ToolMessage` | Resultado de la tool que vuelve al modelo | Aparece en `messages` entre el tool call y la respuesta |

## Código mínimo
```python
from langchain.agents import create_agent
from local_model import get_model           # qwen3:8b en <ollama-host>, reasoning=False → [00 Setup lab local](../setup-lab-local.md)

agent = create_agent(
    model=get_model(),
    tools=[tool1],
    system_prompt="You are an arithmetic wizard. Use your tools to calculate the square root and square of any number.",
)

# Ver el agente paso a paso en vez de un invoke "mudo"
for step in agent.stream({"messages": [question]}, stream_mode="updates"):
    for node, upd in step.items():
        m = upd["messages"][-1]
        print(f"[{node}]", m.tool_calls if getattr(m, "tool_calls", None) else m.content)
```

Salida esperada: `[model]` con el tool call (`x: 467`) → `[tools]` con `21.61…` → `[model]` con la respuesta final.

## Diagnóstico por capas (cuando el agente "no responde")
Probar de abajo hacia arriba; la primera capa que falla es el problema.

| Capa | Prueba | Si falla → |
|---|---|---|
| 1. Red | `requests.get(OLLAMA_URL).text` → "Ollama is running" | IP, firewall, `OLLAMA_HOST=0.0.0.0` |
| 2. Ollama | `POST /api/chat` directo con `"think": False` | Server, RAM, modelo |
| 3. Tool calling | `POST /api/chat` con `"tools": [...]` → `tool_calls` | El modelo no soporta tools |
| 4. Agente | `agent.stream(..., stream_mode="updates")` | LangChain / kernel |

En el server: `ollama ps` (modelo cargado, CPU, contexto) y el log de Ollama (`POST /api/chat` desde `<ip-cliente>`).

## 🧠 Lecciones aprendidas
| # | Problema | Causa | Solución | Regla |
|---|---|---|---|---|
| 1 | El agente nunca terminaba y el server no recibía ninguna petición (`ollama ps` vacío, sin `POST` en el log) | Un `invoke` anterior quedó colgado sin timeout y bloqueó el kernel; las celdas nuevas quedaron **en cola** detrás de esa | Kernel → Restart y correr todo desde arriba | Celda en `[*]` + server sin peticiones = kernel bloqueado, no es el modelo |
| 2 | `NameError: name 'OLLAMA_URL' is not defined` | Reiniciar el kernel borra todas las variables | Volver a correr imports, `tool1` y `question` (o Run All) | Después de reiniciar, correr desde la primera celda |
| 3 | Sospecha de que el modelo no soportaba tools | — | `ollama show qwen3:8b` → Capabilities: `tools` ✅ (gemma4 también) | Un modelo sin tools **falla rápido** con error 400, no se cuelga |
| 4 | Duda de si había dos servidores Ollama | — | Comparar `/api/ps` y `/api/tags` desde el notebook con `ollama ps`/`ollama list` en el server | Mismo resultado en ambos lados = un solo server |
| 5 | La primera llamada tardó ~21 s | Carga del modelo en RAM (~18 s); recarga si cambia `num_ctx` (4096 → 8192) | Normal; el modelo queda cargado 5 min | Cambiar `num_ctx` entre llamadas obliga a recargar |
| 7 | El agente respondió "el cuadrado de 467 es **217,489**" sin que nadie lo pidiera, y está **mal** (es 218,089) | El system prompt menciona "square root **and square**", pero solo existe la tool de raíz. El modelo calculó el cuadrado "de memoria" | Agregar una tool `square` o quitar "square" del system prompt | Si no hay tool para algo, el LLM lo inventa. La aritmética se hace en tools, no en el modelo |
| 6 | Velocidad baja | CPU sin GPU: **~5,7 tokens/s** de generación, ~30 tok/s leyendo el prompt | `reasoning=False` (ya en `get_model()`) | Con thinking activo, cada paso costaría minutos |
| 8 | `ModuleNotFoundError: No module named 'local_model'` | El notebook de tools está en una subcarpeta; el kernel busca imports en la carpeta del notebook y `local_model.py` está en la raíz | Primera celda con `sys.path.insert(...)` que sube hasta encontrar el script | Ver [00 Setup lab local](../setup-lab-local.md); la misma celda en todos los notebooks |

### Medición real (qwen3:8b, CPU, ctx 8192)
| Paso | Tokens generados | Tiempo |
|---|---|---|
| Modelo → tool call | 22 | 13,7 s (incluye 5 s de carga) |
| Tool `tool1` | — | instantáneo |
| Modelo → respuesta final | 55 | 11,6 s |
| **Total** | | **~25 s** |

> `temp = 0.000` y pocos tokens en el log confirman que el thinking está apagado.

## Cómo leer la respuesta
`response["messages"]` queda así:
1. `HumanMessage` — la pregunta
2. `AIMessage` con `content=''` y `tool_calls=[{'name': 'square_root', 'args': {'x': 467}}]`
3. `ToolMessage(content='21.61…', tool_call_id=...)` — el resultado de Python
4. `AIMessage` — la respuesta final

`response["messages"][1].tool_calls` muestra qué pidió el modelo; `usage_metadata` muestra tokens por paso.

## Trampas para el examen
- El loop de `create_agent` alterna los nodos **model** y **tools** hasta que el modelo responde sin `tool_calls`.
- La docstring de la tool **es** la descripción que usa el modelo para decidir: escribirla bien importa.
- `stream_mode="updates"` muestra cada nodo; `"values"` muestra el estado completo en cada paso.
