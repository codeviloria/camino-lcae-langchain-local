# M1.2 Prompting

## Resumen
- `create_agent(model, system_prompt=...)` define el rol y las reglas del agente.
- **Few-shot**: se le dan ejemplos al modelo para que copie el formato de respuesta.
- **Structured prompts**: instrucciones explícitas de formato dentro del prompt.
- **Structured output**: `response_format=PydanticModel` → el resultado queda en `response["structured_response"]` como objeto tipado.

## Conceptos clave
| Técnica | Cómo | Nota |
|---|---|---|
| Few-shot en texto | Ejemplos `User:/Scifi Writer:` dentro del system prompt | Un modelo grande deduce el formato; uno pequeño no |
| Few-shot como mensajes | `HumanMessage` / `AIMessage` reales antes de la pregunta | La forma más confiable con modelos chat |
| Formato explícito | "Respond ONLY with…" | Necesario con modelos locales pequeños |
| Structured output | `response_format=CapitalInfo` (Pydantic) | En Ollama usa **ToolStrategy** → el modelo debe soportar tools |

## Código mínimo
```python
from pydantic import BaseModel
class CapitalInfo(BaseModel):
    name: str; location: str; vibe: str; economy: str

agent = create_agent(model=get_model(),            # qwen3 → soporta tools
                     system_prompt="You are a science fiction writer...",
                     response_format=CapitalInfo)
agent.invoke({"messages": [question]})["structured_response"]

# Alternativa sin tools (sirve con gemma3): JSON schema nativo de Ollama
get_model("gemma3:4b").with_structured_output(CapitalInfo, method="json_schema").invoke("...")
```

## 🧠 Lecciones aprendidas
| # | Problema | Causa | Solución | Regla |
|---|---|---|---|---|
| 1 | El modelo inventó "Lunaria" pero agregó varios párrafos | Few-shot implícito: los modelos de 4B/8B no deducen "solo el nombre" | Escribir la regla explícita **o** poner los ejemplos como `HumanMessage`/`AIMessage` | Con modelos locales, decir el formato explícitamente; few-shot como mensajes reales |
| 2 | "¿Dónde se pregunta por la Luna?" | La pregunta está en la variable `question`, definida en una celda anterior | `print(question)` | Revisar variables heredadas de celdas anteriores |
| 3 | `inspect.signature(get_model)` seguía mostrando `qwen3:8b` | Muestra el **default** de la función, no el modelo creado | `print(model.model)` o `response_metadata["model_name"]` | Para saber qué modelo se usó: mirar el objeto o el trace |
| 4 | `response_format` con gemma3 → `ResponseError: gemma3:4b does not support tools (400)` | Con Ollama, `create_agent` usa **ToolStrategy** (el esquema Pydantic se vuelve una tool) | Usar `qwen3`, o `with_structured_output(..., method="json_schema")` sin agente | gemma3: prompts y texto. qwen3: tools, agentes y structured output |
| 5 | Con `[1]` se tomaba el mensaje equivocado | Con few-shot por mensajes, el historial es más largo | Usar `response["messages"][-1]` | Leer siempre la última respuesta con `[-1]` |
| 6 | Con `qwen3` el `structured_response` salió `name='The Moon'`, `location='Luna'` | El esquema solo tiene nombres de campo; el modelo no sabe que `name` es un nombre **inventado** | Describir cada campo: `name: str = Field(description="Invented name of the capital city")` | En Pydantic, `Field(description=...)` es parte del prompt |

## Trampas para el examen
- `response_format` → **ToolStrategy** (tool calling) vs **ProviderStrategy** (structured output nativo del proveedor).
- Resultado tipado en `response["structured_response"]`; el texto sigue en `messages`.
- Un prompt que funciona en un modelo puede fallar en otro → evaluar con datasets (dominio Test).
