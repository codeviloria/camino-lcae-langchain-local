# M1.8 · Human-in-the-loop

> **Estado:** ✅ · **Fecha:** 2026-10-06 · **Labs:** `python/m1/m1.8_hitl.py`, `m1.8_hitl_respond.py`, `m1.8_homework_filled.py` · **Modelo:** Nemotron 3 Ultra (OpenRouter `:free`)

## 🧸 La idea en simple
HITL es el **botón de "¿confirmas?"** antes de una acción delicada. El agente prepara el email, se **pausa**, guarda todo en el checkpointer y espera. Tú apruebas, editas o rechazas, y el agente sigue desde el mismo punto con `Command(resume=...)`.

## 📚 Conceptos clave
- 4 piezas: **`interrupt_on`** (qué tools pausan) · **checkpointer** (guarda la pausa) · **`thread_id`** (para reanudar la misma) · **`Command(resume={"decisions": [...]})`**.
- `interrupt_on={"send_email": True}` o `{"send_email": {"allowed_decisions": ["approve", "edit", "reject"]}}`.
- Decisiones: `approve` (tal cual) · `edit` (cambia args: `edited_action`) · `reject` (no ejecuta, avisa al agente) · `respond` (tu texto **es** el resultado de la tool, para `ask_user`).
- `invoke(..., version="v2")` → `result.interrupts` y `result.value["messages"]`.
- `when`: predicado opcional. Si devuelve `False`, la llamada se aprueba sola sin pausa.

## 🎯 Para el examen
- Trampa clave: **nunca uses `respond` para bloquear** una tool con efectos (`send_email`). El modelo lee tu texto como resultado exitoso y puede creer que el email se envió. Para bloquear: `reject`.
- HITL **requiere** checkpointer: sin él no hay dónde guardar la pausa.
- Editar mucho los argumentos puede hacer que el modelo replantee y vuelva a llamar la tool: edita poco.

## 🧠 Mnemotecnia
**"A-E-R-R":** Aprobar, Editar, Rechazar, Responder (este último solo para preguntas).
