# M1.7 · Messages, threads y checkpointers

> **Estado:** ✅ · **Fecha:** 2026-10-06 · **Labs:** `python/m1/m1.7_messages_threads_checkpointers.py`, `m1.7_homework_filled.py` · **Modelo:** Nemotron 3 Ultra (OpenRouter `:free`)

## 🧸 La idea en simple
El checkpointer es un **archivador**; cada thread es una **carpeta**; el `thread_id` es la **etiqueta** de la carpeta. Si vuelves con la misma etiqueta al mismo archivador, el agente retoma la conversación. Otra etiqueta, o un archivador nuevo, y empieza de cero.

## 📚 Conceptos clave
- **Messages:** user → `AIMessage` (texto o `tool_calls`) → `ToolMessage`. El agente construye un historial, no manda un solo prompt.
- **Thread:** una conversación, identificada por `config={"configurable": {"thread_id": "..."}}`.
- **Checkpointer:** `create_deep_agent(..., checkpointer=MemorySaver())`. Guarda el state de cada thread.
- `MemorySaver` vive en RAM del proceso: no sobrevive a un reinicio. En producción: `PostgresSaver`, Redis o la persistencia de LangGraph Platform.
- **Time travel:** `agent.get_state_history(config)` lista los checkpoints (el más reciente primero); invocar con el `config` de uno viejo sigue desde ahí sin borrar los nuevos.

## 🎯 Para el examen
- Sin checkpointer, el `thread_id` no sirve: no hay dónde guardar el historial.
- Trampa: "mismo `thread_id` = misma memoria". Solo si es la **misma instancia** de checkpointer.
- `MemorySaver` = solo desarrollo local.

## 🧠 Mnemotecnia
**"Archivador, carpeta, etiqueta":** checkpointer, thread, `thread_id`.
