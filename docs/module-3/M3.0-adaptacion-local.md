Todo el módulo gira en torno al **middleware** de `create_agent`: código que se engancha al ciclo del agente para controlar el historial, pedir aprobación humana o cambiar modelo, prompt y tools en cada llamada.

## Cómo correr el proyecto 3.5 con Agent Chat UI
Requisitos: Node 18+ y `pnpm` (`npm install -g pnpm`).

Terminal 1 (servidor del agente):
```bash
cd notebooks/module-3
uv run langgraph dev
```
Terminal 2 (interfaz de chat):
```bash
cd notebooks/module-3/agent-chat-ui
cp .env.example .env
pnpm install
pnpm dev
```
Abrir `http://localhost:3000` → Deployment URL `http://localhost:2024`, Assistant ID `agent`. Para el servidor local no hace falta `LANGSMITH_API_KEY`.

- `langgraph.json` apunta a `./3.5_email_agent.py:agent` y al `.env` de la raíz (`../../.env`).
- En la UI, el HITL aparece como un **interrupt** con botones para aprobar, editar o rechazar el `send_email`.
- `agent-chat-ui/.gitignore` ya excluye `.env`, `node_modules` y `.next/`.

## 🎯 Para el examen (adelanto, dominio Build)
| Hook / decorador | Cuándo corre | Para qué |
|---|---|---|
| `@before_agent` | Una vez, antes de empezar | Limpiar o preparar el state (borrar `ToolMessage`s) |
| `@before_model` / `@after_model` | Antes o después de **cada** llamada al modelo | Recortar mensajes, validar la salida |
| `@wrap_model_call` | Envuelve **cada** llamada al modelo (`handler(request)`) | Cambiar **modelo** o **tools** con `request.override(...)` |
| `@dynamic_prompt` | Antes de cada llamada | Generar el system prompt desde state o context |
| `@wrap_tool_call` | Envuelve **cada** ejecución de tool | Reintentos, errores, logs (equivale al interceptor MCP de M2.4, pero para todas las tools) |
| `SummarizationMiddleware` | Cuando se pasa el `trigger` (tokens o mensajes) | Resumir el historial y conservar `keep` mensajes |
| `HumanInTheLoopMiddleware` | Antes de las tools de `interrupt_on` | Pausa → `__interrupt__` → `Command(resume={"decisions": [...]})` con el **mismo thread_id** (requiere checkpointer) |

- **Trampas probables:** HITL sin checkpointer no puede reanudar; `request.override` devuelve un request nuevo (no muta); 🚨 **ocultar una tool (`override(tools=...)`) no la bloquea**: si el modelo la nombra, se ejecuta; el bloqueo real va en `@wrap_tool_call` (ver M3.4).
