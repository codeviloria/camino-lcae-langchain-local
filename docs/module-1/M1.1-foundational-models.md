# M1.1 Foundational Models

## Resumen
- `init_chat_model()` crea un chat model de cualquier proveedor con una sola interfaz.
- `.invoke()` devuelve un `AIMessage` (`.content`, `.response_metadata`).
- `create_agent()` envuelve el modelo en un agente (grafo LangGraph). Entrada/salida: `{"messages": [...]}`.
- El historial se pasa como lista de `HumanMessage` / `AIMessage`.
- Streaming: `agent.stream(..., stream_mode="messages")` → tuplas `(token, metadata)`.

## Variables del `.env` — qué hace falta con Ollama local
| Variable | ¿Necesaria? | Para qué |
|---|---|---|
| `OPENAI_API_KEY` | ❌ | Solo si usas `gpt-*` |
| `ANTHROPIC_API_KEY` | ❌ | Solo si usas `claude-*` |
| `GOOGLE_API_KEY` | ❌ | Solo si usas Gemini |
| `LANGSMITH_API_KEY` + `LANGSMITH_TRACING=true` | ⚠️ No para correr, **sí para el examen** | Tracing, datasets, evals, deployment, monitoreo (3 de 4 dominios del LCAE son LangSmith). Plan Developer gratuito. |
| `LANGSMITH_PROJECT` | Opcional | Nombre del proyecto de traces |

> Si dejas `LANGSMITH_TRACING=true` sin key válida, el código corre pero lanza warnings al subir traces. Sin key → `LANGSMITH_TRACING=false`.

`.env` mínimo:
```env
LANGSMITH_API_KEY=lsv2_...
LANGSMITH_TRACING=true
LANGSMITH_PROJECT=lca-intro-langchain
OLLAMA_HOST=http://<ollama-host>:11434     # server Ollama del lab
```

## Adaptación del notebook a Ollama
> La versión final de esta adaptación es **`local_model.py`** → `get_model()`. Ver [00 Setup lab local](../setup-lab-local.md).

```bash
pip install -U langchain langchain-ollama python-dotenv
ollama pull qwen3:8b      # o llama3.1:8b — debe soportar tool calling para agentes
```
```python
from dotenv import load_dotenv; load_dotenv()
from langchain.chat_models import init_chat_model

model = init_chat_model("ollama:qwen3:8b", temperature=1.0)        # reemplaza gpt-5-nano
# servidor remoto: init_chat_model("ollama:qwen3:8b", base_url="http://IP:11434")

# celda Gemini → ChatOllama directo
from langchain_ollama import ChatOllama
model = ChatOllama(model="qwen3:8b")

from langchain.agents import create_agent
agent = create_agent(model)                 # pasar el objeto, no el string "gpt-5-nano"
```
- `response_metadata` cambia: Ollama muestra `eval_count`, `total_duration`, etc. en vez de `token_usage` de OpenAI.
- Modelos pequeños sin tool calling fallan cuando el curso agregue tools (M1.2+).

## Las 3 formas de crear el agente (solo se necesita UNA)
`from langchain.agents import create_agent` solo importa la función; el agente existe cuando se ejecuta `agent = create_agent(...)`. Cada celda **sobrescribe** `agent`: queda activo el último ejecutado.
| Forma | Código | Cuándo |
|---|---|---|
| Objeto modelo | `create_agent(model=model)` | Control total de parámetros (base_url, temperature, reasoning) |
| Helper | `create_agent(model=get_model())` | Mi lab: Ollama remoto, `reasoning=False` |
| String | `create_agent("ollama:qwen3:8b")` | Rápido; lee `OLLAMA_HOST` del `.env`; sin parámetros extra |

**Hallazgo (lab):** con la forma string, `qwen3:8b` piensa en silencio → `eval_count` 448 tokens para ~110 visibles, 79 s. Con `get_model()` (`reasoning=False`) responde mucho más rápido.

## 🧠 Lecciones aprendidas
> Problema → causa → solución → regla para no repetirlo.

| # | Problema | Causa | Solución | Regla |
|---|---|---|---|---|
| 1 | Las celdas del curso usan `gpt-5-nano`, Claude y Gemini | No tengo APIs de pago | Reemplazar por Ollama remoto (`<ollama-host>`) con `get_model()` o `init_chat_model("ollama:...", base_url=...)` | Dejar la celda original comentada (`## Esto no lo corrí…`) junto a la adaptada |
| 2 | **403 Forbidden** al subir traces a LangSmith | La key en `.env` tenía `API ` pegado al inicio (len 55 vs 51) | Dejar solo `lsv2_pt_...`, sin prefijos ni espacios | Verificar la key con el `print` de los primeros caracteres y el largo; una PAT válida mide 51 |
| 3 | El 403 siguió después de corregir el `.env` | El tracer de LangSmith guarda en caché la key con la que arrancó el kernel; `load_dotenv()` no sobrescribe sin `override=True` | **Reiniciar el kernel** | Cada vez que se edita el `.env` → Restart Kernel |
| 4 | `create_agent("ollama:qwen3:8b")` apuntaba a localhost | La forma string no acepta `base_url` | Agregar `OLLAMA_HOST=http://<ollama-host>:11434` al `.env` | Forma string = parámetros por variables de entorno |
| 5 | El agente tardó 79 s en una respuesta corta | `qwen3` razona en silencio sin `reasoning=False`: `eval_count` 448 vs ~110 tokens visibles | Usar `create_agent(model=get_model())` | Revisar `eval_count` vs largo visible; para el curso, siempre `get_model()` |
| 6 | Duda: ¿hacen falta las 3 formas de `create_agent`? | Son alternativas; cada celda sobrescribe `agent` | Basta **una**; la activa es la última ejecutada | El `import` no crea nada; el agente nace en `agent = create_agent(...)` |
| 7 | La API key de LangSmith quedó visible en una captura | Compartí la pantalla del `.env` | Revocar la key y crear una nueva | Nunca compartir capturas del `.env` ni de secretos |
| 8 | `gemma3:4b` no sirve para agentes | No soporta tool calling en Ollama | Usar `qwen3` para `create_agent` | Para agentes con tools: un modelo que soporte tools |
| 9 | Throughput bajo, ~5.8 tok/s con un 8B | Posible offload a CPU | Revisar `ollama ps` (debe decir 100% GPU) | Medir con `eval_count / eval_duration` |

## Trampas para el examen
- String `"proveedor:modelo"` en `init_chat_model` / `create_agent` infiere el proveedor.
- `create_agent` devuelve un grafo compilado → `invoke`, `stream`, `ainvoke`.
- `model.invoke()` → `AIMessage`; `agent.invoke()` → estado `{"messages": [...]}` con todo el historial.
- `usage_metadata` (estándar LangChain) vs `response_metadata` (crudo del proveedor).
- `stream_mode="messages"` = tokens; `"updates"` = pasos del grafo; `"values"` = estado completo.
